# Análisis Crítico

---

## Introducción

El desarrollo de la propuesta AuditChain implicó la toma de diversas decisiones tanto a nivel tecnológico como de diseño. Estas decisiones fueron orientadas a construir una solución funcional, escalable y centrada en el usuario, considerando los requerimientos del problema planteado.

---

## Decisiones tecnológicas

Para el desarrollo del sistema se seleccionaron tecnologías modernas que permiten construir una arquitectura robusta y flexible.

| Tecnología  | Justificación |
|------------|--------------|
| Flutter    | Permite desarrollar aplicaciones móviles modernas y multiplataforma, facilitando la adaptación a distintos dispositivos. |
| FastAPI    | Ofrece un alto rendimiento para la construcción de APIs, permitiendo una comunicación eficiente entre los componentes del sistema. |
| PostgreSQL | Proporciona una base de datos confiable y estructurada, ideal para la gestión de información crítica como auditorías. |
| GitHub     | Permite el control de versiones y facilita el trabajo colaborativo en el desarrollo del proyecto. |

Estas tecnologías permiten construir una solución moderna, escalable y mantenible.

---

## Decisiones de arquitectura

Se opta por una arquitectura distribuida compuesta por tres capas principales: web, aplicación móvil y backend.

| Elemento        | Justificación |
|----------------|--------------|
| Separación web/móvil | Permite diferenciar funciones entre administración y ejecución en terreno |
| Backend centralizado | Facilita la gestión de datos y la comunicación entre sistemas |
| Uso de API | Permite la integración entre los distintos componentes |

Esta arquitectura permite una mejor organización del sistema y facilita su crecimiento futuro.

---

## Decisiones de diseño

El diseño del sistema se enfoca en la claridad visual y la facilidad de uso, especialmente en la visualización de datos.

| Elemento de diseño | Justificación |
|-------------------|--------------|
| Dashboard         | Permite visualizar información relevante de forma rápida |
| Uso de colores    | Facilita la identificación de estados (completado, pendiente, alerta) |
| Diseño responsive | Permite adaptar la interfaz a distintos dispositivos |
| Mockups previos   | Permiten validar la experiencia de usuario antes del desarrollo |

Estas decisiones buscan mejorar la experiencia del usuario y facilitar la interpretación de la información.

---

## Enfoque del usuario

El sistema se diseña considerando dos tipos principales de usuarios, cada uno con necesidades específicas.

| Usuario        | Enfoque |
|---------------|--------|
| Administrador | Control y supervisión del sistema |
| Auditor       | Ejecución de auditorías en terreno |

Este enfoque permite adaptar la solución a distintos contextos de uso.

---

## Evaluación de la propuesta

La propuesta desarrollada cumple con los objetivos planteados, permitiendo visualizar una solución completa que integra distintas tecnologías y componentes.

No obstante, al tratarse de un prototipo, existen limitaciones en cuanto a implementación real, las cuales deberán ser abordadas en futuras etapas.

---

## Conclusión del análisis

Las decisiones tomadas en el desarrollo de AuditChain permiten construir una base sólida para una solución tecnológica moderna, destacando la integración entre plataformas y el enfoque centrado en el usuario.

El sistema presenta un alto potencial de desarrollo y mejora, lo que lo convierte en una propuesta viable para su implementación futura.
